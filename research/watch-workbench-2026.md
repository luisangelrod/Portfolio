# A thread becomes a laboratory

Prepared for Luis Rodriguez • 6 September 2026

## Decision

Build the public-facing experience as an efficient browser application. Keep the existing Unreal Engine 5.8.2 native companion for a separate, higher-fidelity path. The core watch instrument should work without a paid API, a GPU streaming server, or a camera. Its personal foundation is Luis's father's interest in Rolex and Omega.

The welcome is an authored transformation: a suspended network gathers, becomes bridge and tower studies, resolves into a watch, then opens the existing portfolio. Its geometric morph is distinct from the homepage's physical tension experiment. Visitors can skip, pause, or replay it; direct project links remain direct.

## Evidence that changes the implementation

**Watch mechanism.** Openmovement's public technical sheet provides tooth counts, paired gear modules, and timing relationships. The implemented OM10-based schematic uses those values. The mechanical layout, tooth profiles, escape-wheel diameter, case, and balance presentation are original illustrations. The balance study does not contain a working pallet-contact solver. The source is dated 14 March 2021, contains revision and accuracy caveats, and licenses its material CC BY-SA 3.0. The adaptation retains attribution and identifies changes. The official STEP downloads require a user account; the free tier advertises access. No account or STEP assembly was obtained during this build. [Technical sheet](https://openmovement.org/documents/OM10/OM10_Technical_Information_20210314.pdf), [membership](https://openmovement.org/membership-levels/).

**The two watch references.** Rolex's Submariner Date 126610LN documents a 41 mm case, automatic calibre 3235, and approximately 70-hour reserve. Omega's Speedmaster Moonwatch 310.30.42.50.01.002 documents a 42 mm case, manual calibre 3861 chronograph, and 50-hour reserve. These are collection/reference cards, not reconstructed internals. Public product documents do not establish CAD or imagery redistribution rights. [Rolex](https://www.rolex.com/watches/submariner/m126610ln-0001), [Omega product sheet](https://www.omegawatches.com.hk/media/pdf/watches/product-sheet/hk/en-gb/31030425001002-en-gb.pdf).

**Rendering.** Three.js recommends WebGLRenderer for pure WebGL2 work. Its WebGPU renderer offers fallback, but remains experimental and requires migration of existing custom materials and EffectComposer workflows. This project already has a functioning Three.js laboratory stack. Retaining it avoids an engine migration with no demonstrated user benefit. Heavy scene code and optional exporters load separately. [Renderer guidance](https://threejs.org/manual/en/webgpurenderer), [pixel sizing](https://threejs.org/manual/en/responsive.html).

**Hand interaction.** Google MediaPipe supplies a hand landmark detector and web runtime. The implementation uses the official package 1.0.1 and a locally bundled model in a worker. One pinch rotates the view; two pinches preview separation; release commits. It starts only after the visitor asks, requests no microphone, and sends no video to a backend. Its model card describes experimental limitations in varied conditions. Package/model licensing and source notice accompany the bundled files. Actual camera tracking remains a hardware-verification item. [Guide](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker), [web guide](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js), [model card](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20Hand%20Tracking%20(Lite_Full)%20with%20Fairness%20Oct%202021.pdf).

**Unreal and DLSS.** Local inspection found an M3 Pro Mac with 18 GB RAM and Unreal Engine 5.8.2. NVIDIA's current DLSS page offers a UE5.8 plugin, but DLSS requires NVIDIA RTX Tensor cores; it cannot accelerate this Apple GPU or browser graphics. Unreal's built-in TSR supports Mac Metal. It is an optional native benchmarking candidate, not an implemented improvement in this browser build. UE4 supplies no established benefit here. [NVIDIA](https://developer.nvidia.com/rtx/dlss), [Epic Mac requirements](https://dev.epicgames.com/documentation/unreal-engine/macos-development-requirements-for-unreal-engine), [TSR](https://dev.epicgames.com/documentation/en-us/unreal-engine/temporal-super-resolution-in-unreal-engine).

**Native streaming and MCP.** Epic documents Mac VideoToolbox support for Pixel Streaming and mobile Safari clients. Internet operation still needs a running host, signalling, and sometimes TURN relay bandwidth. The experimental Unreal MCP is local editor automation; it is not an authenticated multiplayer backend. Installed plugins are not evidence that a live bridge or streamed watch scene exists. Native streaming was not activated by this web build. [Pixel Streaming](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-pixel-streaming-reference), [networking](https://dev.epicgames.com/documentation/en-us/unreal-engine/hosting-and-networking-guide-for-pixel-streaming-in-unreal-engine), [Unreal MCP](https://dev.epicgames.com/documentation/unreal-engine/unreal-mcp-in-unreal-editor).

## Free software versus an operating service

The implemented collaboration service uses the existing Node preview and local disk, avoiding a paid account for development. It synchronizes study state, selection, playback, and saved notes through expiring bearer invitations. It checks revisions and preserves unsent work on conflicts. Every participant must use the same listener and reachable origin. Different preview servers have isolated stores. A localhost link is not an Internet link. Public hosting or a private network endpoint, TLS, backups, and real cellular testing remain deployment work.

A hosted collaboration service such as Liveblocks is an alternative, not a requirement. Its development tier does not establish unlimited free production operation. [Liveblocks documentation](https://liveblocks.io/docs/get-started/react), [pricing](https://liveblocks.io/pricing).

Tavily supplies search/extraction APIs and an MCP, with a published free credit allowance. WatchBase supplies paid-per-entry watch specifications but excludes image sublicensing. Neither supplies accurate hidden watch internals from a photograph. No credentials were configured and no paid lookup was performed. The existing local photo-inspection companion remains accessible. [Tavily MCP](https://docs.tavily.com/documentation/mcp), [Tavily pricing](https://www.tavily.com/pricing), [WatchBase](https://datafeed.watchbase.com/).

## Further capabilities worth building

1. Obtain and inspect the authorized OM10 STEP assembly, preserve component identities and units, then replace schematic geometry selectively. The LGPL Open Cascade importer can preserve an assembly hierarchy while triangulating for display; it does not create joints or a solver. [occt-import-js](https://github.com/kovacsv/occt-import-js).
2. Add real research retrieval only after selecting a runtime API and setting usage limits. Require reference confirmation, evidence links, and explicit missing-model states.
3. A cinematic native watch scene can reuse the same part identifiers and ratios. Blender is a free authoring option for licensed/original assets and morph targets. Use a measured native TSR comparison before enabling heavier effects. [Blender license](https://www.blender.org/about/license/), [glTF export](https://docs.blender.org/manual/en/5.1/addons/import_export/scene_gltf2.html).
4. AR Quick Look can place an exported USDZ snapshot on a table; it is not the full live collaborative editor. The build exports snapshots with meter scaling and embedded attribution. Real iPhone validation is still required. [Apple Quick Look](https://developer.apple.com/documentation/ARKit/previewing-a-model-with-ar-quick-look).
5. The browser tool surface uses the project's document.modelContext registration when available. Current Chrome guidance uses that interface; standard buttons remain independent of this experimental capability. [WebMCP imperative API](https://developer.chrome.com/docs/ai/webmcp/imperative-api).

## Research quality and stopping point

Primary sources and current local inspection support the consequential choices: open data availability, licensing gates, paired ratios, GPU compatibility, browser rendering, and remote-service requirements. Native and watch-data research lanes independently checked their evidence; the coordinator re-opened the highest-impact sources and integrated the findings. Public search cannot establish that no private brand CAD agreement exists. No such agreement or public blueprint API was verified. Further general searches would not remove the remaining account, CAD-inspection, deployment, and physical-device verification gates.
